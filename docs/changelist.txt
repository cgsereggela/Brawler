issues to fix:
- bots ignore the 1.4 arena features. They never shoot a hanging platform's chains, even with an enemy standing in its landing spot, and they treat drifting platforms as solid ground, so they fall a lot in Drift arenas. Have them shoot a chain when its drop would land on an enemy, and allow for a drift dipping and sliding when they jump onto or off one
- editorcheck's controller step "B on a controller didn't delete the block" fails about one run in three. Find the race (probably the cursor or the input frame landing before the editor is ready) and make the step reliable, so a red editorcheck always means a real bug
- themebench on D3D12 sometimes gives odd readings: one 1.4.0 run timed Mainframe at 5.7 ms against about 22 ms in every other run, and an earlier run segfaulted at exit after finishing every theme. Check that each theme's timing starts only once it has loaded and drawn, and that the bench quits cleanly

features to add:
- conveyor belts: strips of ground that carry players, props and dropped flags along, in either direction. Seeded like the other arena features (never needed to reach a spawn), plus a map editor tool and map code support
- portal pairs: two linked rings. A player or bullet that enters one comes out of the other with the same speed, turned to match the exit's facing. Seeded, plus a map editor tool and map code support; bots path through them
- training range: a solo mode from the main menu where you pick any cards from a browsable list (rares and curses included) and try them on target dummies and a passive bot, with a reset button. It helps players learn 100+ cards without playing a whole match
- match stats on the match-over screen: a Stats tab with each player's kills, damage dealt and taken, accuracy and blocks for the match. The game already records all of this for the card balance stats
- daily challenge: one seeded arena, mode and starting card set per day, played against Hard bots, with your best result for the day kept in your profile. The same seed for everyone, so friends can compare

performance improvements
- cut AvatarArt's CPU cost. Drawing one character takes about 0.22 ms of C# (Debug build) even batched, so the HUD's chip heads cost about 0.9 ms a frame and the fighters as much again: profile Solve and the per-shape array allocations, and consider caching each look's static parts (mask, hair, hat) as triangles that only get a transform per frame
- batch the backdrop's additive motes layer and window lights. The motes layer alone is ~250 draw calls and ~6 ms (circles, arcs and rects drawn one by one with antialiasing), and DrawWindows adds a round rect per lit window, which is why the city themes (Mainframe 48 ms, Neon Night 39 ms) are the slowest. Use TriBatch for both, or bake the windows into the land texture and only animate their alpha
- bake static map decorations into the ground texture. MapNode's solids layer only redraws on change, but Godot still replays every cached command each frame (~140 draw calls for shadows and decos). Painting them into the ground image once costs one textured rect
- avoid antialiased=true on DrawCircle, DrawArc and DrawPolyline in per-frame drawing. Each one adds a feathered edge mesh and its own draw call, and 2D MSAA (on in project settings) already smooths edges; measured that MSAA and HDR 2D themselves cost nothing noticeable here
- add a --perfstats flag that prints draw calls, primitives, frame/process/physics ms each second (Performance monitors), plus a per-layer split mode that hides one layer at a time, so these numbers can be re-measured after each fix. Target: under 300 draw calls and 16.6 ms in --themebench, on D3D12 as well as Vulkan
- with vsync on (the default) on this 59 Hz screen, frames that miss 16.9 ms judder between 59 and 30 fps. Once the fixes above land this mostly goes away; an adaptive vsync option (DisplayServer.VSyncMode.Adaptive) in the display settings would soften it on slower machines. Not measured separately
