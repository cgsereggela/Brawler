performance improvements (ranked by expected saving; measured 2026-10-25 with --themebench on Vulkan, v2.0.0 averages 5.4 ms/frame. Of that, C# drawing and logic take ~3 ms, the render thread ~0.8 ms CPU and ~0.85 ms GPU, and the rest is engine overhead)
- [~1.1 ms on every theme, measured] HUD player chips: HudUI._Draw runs a full AvatarArt.Draw for every player's chip head every frame, only so the heads can breathe and blink. That's 0.8 ms of C#, plus the engine's cost for the triangles; skipping the heads took the bench from 5.37 to 4.26 ms. Draw each chip head into a small cached texture (redrawn only when the look, colour or scale changes) and do the breathe as a transform and the blink as a tiny overlay. Or simply redraw the heads at ~10 Hz
- [~0.7 ms on average, up to 2.3 ms, measured] animated decorations: on themes with DecoAnimated, MapNode.DrawAnim redraws every decoration every frame, even the ones that don't move. Turning it off saved 2.3 ms on Elder Forest, 1.5 on Dungeon Depths, 1.3 on Deep Reef and 1.0 on Sunset Peaks (the slowest themes). Draw the still decorations once in the cached solids layer and only the moving ones (grass, flames, drips) per frame. Or do the sway in a vertex shader on a mesh built once, so nothing is re-recorded per frame
- [~0.3-0.5 ms, estimated] character art geometry cache: --artbench reads 0.31 ms of C# per character since the 2.0 shading redraw (0.25 before). Hair, hat, eyes, mouth and body are drawn in body space under a transform, so their triangles (feathered edges included) can be built once per look, colour and facing and replayed with each frame's transform; only the rig (legs, arm, breathing, blink) needs solving per frame. Wins back most of the 2.0 slowdown and makes the HUD heads cheaper too
- [~0.5-0.8 ms on Mainframe and Neon Night, ~0.1 ms elsewhere, estimated] backdrop land layer: Backdrop redraws _land every frame (0.75 ms of C# on Mainframe, 0.42 on Neon Night) for the lit windows and drifting fog. Keep the layer textures and the windows in a cached item, twinkle the windows with a shader (time uniform, per-window phase in the vertex colour) and move the fog banks with a scrolling texture instead of re-recording them
- [~0.2-0.4 ms, estimated] Arena._Draw: 0.2-0.7 ms of C# per frame (0.69 on Magma Core) re-records saw slots, pools and drifting-platform bodies that hardly change, with antialiased lines and hex colours parsed each frame. Split the static parts into a layer redrawn only on change, and keep only what moves (movers, blades, pool surface) per frame
- [~0.1-0.3 ms, estimated] bake static map decorations into the ground texture. MapNode's solids layer only redraws on change, but Godot still replays every cached command each frame (~140 draw calls for shadows and decos). Painting them into the ground image once costs one textured rect
- [~0.1-0.2 ms, estimated] avoid antialiased=true on DrawCircle, DrawArc and DrawPolyline in per-frame drawing. Each one adds a feathered edge mesh and its own draw call, and 2D MSAA (on in project settings) already smooths edges; measured that MSAA and HDR 2D themselves cost nothing noticeable here
- [~0.05-0.15 ms, plus steadier frame times, estimated] per-frame allocations: drawing allocates 35-45 KB a frame (a gen-0 GC about once a second at 180 fps). The causes are new Color("#hex") parsed inside draw loops (137 in Game/Fx/UI, 29 in Arena.cs alone) and new[] point arrays for every polygon (40 in AvatarArt.cs). Hoist the colours into static readonly fields and reuse scratch arrays
- [~0.05-0.08 ms, measured 0.09 ms] Crosshair._Draw costs 0.09 ms every frame; redraw it only when the aim or its state changes, or make it a small cached texture
- [no saving by itself] add a --perfstats flag that prints draw calls, primitives, frame/process/physics ms each second (Performance monitors), plus a per-layer split mode that hides one layer at a time, so these numbers can be re-measured after each fix. Target: under 300 draw calls and 16.6 ms in --themebench, on D3D12 as well as Vulkan
- [no saving in ms; smoother on slow machines] with vsync on (the default) on this 59 Hz screen, frames that miss 16.9 ms judder between 59 and 30 fps. Once the fixes above land this mostly goes away; an adaptive vsync option (DisplayServer.VSyncMode.Adaptive) in the display settings would soften it on slower machines. Not measured separately
