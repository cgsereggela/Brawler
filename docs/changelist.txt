issues to fix:
- nothing runs the checks except a release. The only workflow, release.yml, fires on a v* tag and runs the unit tests plus --editorcheck; the other ~20 check modes (autotest, autohost/autojoin, padcheck, hazardcheck, vantagecheck, hangercheck, driftcheck, overlaycheck, rebindcheck...) only run when someone remembers to. Add a tools/check.sh that builds once, runs every headless check (and the windowed ones when a display is there), and prints a pass/fail table with each failure's AUTOTEST line; then a CI workflow on every push that runs the unit tests and the headless set
- bot checks can't be replayed. BotBrain's RandomNumberGenerator is never seeded, and autopilot card picks use GD.Randf, so --fixed-fps runs still differ every time (hangercheck took 9-22 s across six runs of the same build). Seed bots and picks from the match seed (or a --seed=N flag), print the seed in every check's result line, and let a failing seed be rerun exactly
- some bot check limits sit inside the run-to-run spread. hazardcheck's pool limit is 40 damage per bot-minute and the 1.4 bots measured 38 and 47 in back-to-back runs, so it was a coin flip; hangercheck's 30 s limit is close to its slowest runs. Once seeded, run each check over a fixed set of seeds (or N runs) and set the limits against the worst of those, not one run
- card effects only get exercised by chance. The unit tests cover card data (ids, categories, stat stacking) but the effect hooks (Homing, Splitter, Explosive, bounce blasts, Vampire, teleport on block...) live in Game/ and run only when --cards=random:N happens to deal them. Add a --cardcheck that plays a short battle holding each card in turn, with error counting on, and checks the card's effect actually fired (a bullet split, a heal, a teleport) where that's observable
- networked play is checked by hand only. --autohost/--autojoin (plus --dropat rejoin, --rematch, --couch) need two processes started by hand, so snapshot, RPC and rejoin regressions only show up in manual testing. Add a check script that starts the host and the client, waits for both, and fails unless both report PASS; run it in CI
- pure maths inside Game/ has no unit tests. BotBrain's LobAim/ArcClear, JumpLands and the ballistic and drop formulas, and GameManager.Sync's snapshot packing don't touch the scene tree but sit outside Logic/, so the test project can't compile them. Move the engine-free parts into Logic/ and test them directly (a lob lands where aimed, a packed snapshot round-trips)
- the unit test runner is one 2,000-line Program.cs with no way to run one area. Split it into files by section and take an optional name filter (dotnet run -- MapCode), so a failure can be rerun on its own

- portal pairs: two linked rings. A player or bullet that enters one comes out of the other with the same speed, turned to match the exit's facing. Seeded, plus a map editor tool and map code support; bots path through them

performance improvements
- cut AvatarArt's CPU cost. Drawing one character takes about 0.22 ms of C# (Debug build) even batched, so the HUD's chip heads cost about 0.9 ms a frame and the fighters as much again: profile Solve and the per-shape array allocations, and consider caching each look's static parts (mask, hair, hat) as triangles that only get a transform per frame
- batch the backdrop's additive motes layer and window lights. The motes layer alone is ~250 draw calls and ~6 ms (circles, arcs and rects drawn one by one with antialiasing), and DrawWindows adds a round rect per lit window, which is why the city themes (Mainframe 48 ms, Neon Night 39 ms) are the slowest. Use TriBatch for both, or bake the windows into the land texture and only animate their alpha
- bake static map decorations into the ground texture. MapNode's solids layer only redraws on change, but Godot still replays every cached command each frame (~140 draw calls for shadows and decos). Painting them into the ground image once costs one textured rect
- avoid antialiased=true on DrawCircle, DrawArc and DrawPolyline in per-frame drawing. Each one adds a feathered edge mesh and its own draw call, and 2D MSAA (on in project settings) already smooths edges; measured that MSAA and HDR 2D themselves cost nothing noticeable here
- add a --perfstats flag that prints draw calls, primitives, frame/process/physics ms each second (Performance monitors), plus a per-layer split mode that hides one layer at a time, so these numbers can be re-measured after each fix. Target: under 300 draw calls and 16.6 ms in --themebench, on D3D12 as well as Vulkan
- with vsync on (the default) on this 59 Hz screen, frames that miss 16.9 ms judder between 59 and 30 fps. Once the fixes above land this mostly goes away; an adaptive vsync option (DisplayServer.VSyncMode.Adaptive) in the display settings would soften it on slower machines. Not measured separately
